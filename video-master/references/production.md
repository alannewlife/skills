# 视频制作与交付

优先使用用户指定或当前环境已有的图片生成、TTS 和 Remotion 能力；工具不支持图片参考时诚实说明，不承诺一致。品牌来源只使用项目 `brand.logo`；它可以为空。配音依已确认的旁白制作，妥善保留分段和时间，凭证不得写进项目。

## 从已确认分镜制作画面

分镜制作前先为每幕列出需要独立出现、移动或聚焦的对象，以及拟用绘画素材、已有素材和代码实现的元素。尽可能保存透明素材、原始层与坐标；在分镜卡片的画面说明中让用户看到分工和未解决的扁平化风险。不要把制作说明写进供用户提交修改的 `notes` 字段。若只有整图，先验证可用的分离或重绘方式，不能假设分离无损；无法在不损坏关键内容的情况下实现独立动效时，明确展示限制，请用户决定重画或接受简化。

设计和绘制分镜场景图时，主动识别需要文字辅助理解的重要节点、关系或步骤，设计简短准确、归属清楚的画面说明，将文字体现在提交审阅的场景图中。文字可在绘图时生成，也可作为独立文字层叠加，保证可读、贴近所说明的内容，不遮挡关键画面；避免给每个元素机械加标签或照搬整段旁白。制作视频时保留已确认场景图中的说明，随对应对象和讲解呈现；仅在动画或旁白确有需要时补充文字。具体是否需要和措辞由故事、画面与用户要求决定。

逐幕建立内部还原清单：对象与细节、视觉样式和比例、相对位置、连接对象和方向、遮挡及先后层级、完整全景、旁白焦点与时间。把每个元素标为绘画素材 `drawn`、代码元素 `code`、可复用的既有独立素材 `existing`、或无需拆分的整体 `group`；记录参考来源和用途。计划应体现实际可获得的素材及工具，不得把代码绘制当作删除或简化重要内容的理由。

- 人物、表情、智能体和复杂插画优先原有独立素材或参考分镜与角色图生成；同组不需独立运动的元素可以整体保留。使用独立素材时核对角色身份、姿态、轮廓、颜色和原图的相对尺寸与位置。
- 准确可改的文字、编号、动态关系线和简单界面可由代码制作；按分镜还原线型、颜色、粗细、连接对象、箭头方向、界面差异和层级。绘画风格强且无需动态变化的线条或界面可以保留为图片的一部分。
- 优先保留原始分层及其位置；仅有整图时，根据可用的图像能力进行合适的分离、遮挡修补或参考重绘。不能把含文字、连线的整图简单硬切后当作完整可动素材，也不能声称分离后一定无损。可保留不需单独活动的整体图层；若无法可靠还原，记录具体差异供用户选择接受或修改。
- 用真实素材按原构图合成完整画面，先对照确认的分镜：对象、局部细节、比例、布局、层次、线条端点、色彩与疏密。镜头可根据旁白聚焦、淡出无关对象，但要回到完整关系；新增标题、标签、Logo 不能遮挡原图关键内容。用户明确要求的改变按其意见执行并记录。

样片发布时，在真实编码视频中选一个可检查完整构图的时间点，用 ffmpeg 或等效工具提取原始视频帧，记录秒数及分镜场景 ID；与该场景原图并列显示。不得用故事板图、参考图或未经渲染的合成图冒充视频截图。样片确认后，为每幕制作带配音的实际视频片段与编码全景帧，连同分工计划在页面逐幕播放并对照确认；已确认的样片可复用。每条线应在相关对象出现后随讲解呈现，镜头应依据旁白逐个聚焦、停稳，最后回到完整全景；对照阶段应检查实际运动，而不只是静态画面。

逐条检查关系线的完整生命周期：确认起点、终点和方向对应实际对象；线条在对象与讲解就绪后出现；对象移动、淡出或退出焦点时，关联线同步移动或淡出；回到全景后关系完整恢复。多分支线逐步出现时，避免主干或分支暂时悬空、连接到尚未出现的对象。检查实际编码视频中入场、镜头切换前后及切换中间、淡出和全景恢复的过程，确认没有残留或孤立线段；不能只检查全景静帧。发现问题先修正再提交审阅。

制作最终视频后，从实际 MP4 的每一幕提取完整关系全景，再与对应已确认分镜逐项检查上述内容；也检查焦点时的相关对象和标题、声音、章节切换、结尾。计算图像差异仅作辅助，不能以相似度分数代替对象和关系的检查。发现明显偏差先修正；不能修正时在页面写明具体差异，等待用户明确接受。只清除已处理意见，不得代用户勾选接受。

`assets/remotion-template/` 是公司线稿风格的可运行参考工程，包含原项目示例人物、Logo 和示例音轨；它不是任意故事的自动生成器。复制到项目后，删除/替换旧项目标题、Logo、音轨和内容，再依当前故事编写场景。其他风格不可假装该模板已验证；自行构建样片供用户确认。可读取已安装的 Remotion 技能了解实现，具体 TTS 和图片工具依环境而定。

确认样片后制作全片，检查 MP4 实际画面与声音、开头结尾、场景切换、文字和音画同步；输出可编辑代码、独立素材、配音和最终文件。不要以原视频预览代替当前项目新视频。缺少工具、配音或视频时说明限制并停在相应阶段。

## 小米 MiMo 配音

在确定配音前说明推荐服务及可选方案；用户选择 MiMo 后，先检查已知凭据位置是否已配置，未配置或合成失败时说明状态并引导用户在页面私密配置或修复。等待时定期仅检查是否配置，不输出凭据；配音设置可能不改变项目 revision，检测到配置后可按用户已选服务尝试合成。用户明确选择其他音源后才可替换，并在样片计划中记录实际服务与音色；凭据状态不等于联网验证成功。

用户可打开页面右上角“配音设置”，按链接到 [小米 MiMo 开放平台](https://platform.xiaomimimo.com/) 登录并在控制台 API Keys 页面创建按量调用 Key，然后在本地页面输入。保存后 Mac 写入当前用户 macOS 钥匙串、Windows 写入当前用户 Windows 凭据管理器，条目名称为 `Video Master / Xiaomi MiMo`；可以在设置页替换或删除。其他系统的页面不支持长期保存，可在启动进程时使用 `MIMO_API_KEY` 环境变量。也识别当前进程的 `XIAOMI_MIMO_API_KEY` 和 `XIAOMIMIMO_API_KEY`；系统凭据优先。状态只描述这些已知位置，不能断言其他应用或不同名称的钥匙串条目里不存在 Key。Key 从不写入项目 JSON、源码、输出、聊天或命令行参数；输入后不会回显。设置页的“已保存”是本地存储状态，不是联网验真；首次合成失败需显示服务错误并保留项目。别让用户在聊天粘贴 Key。

把已确认的旁白写入项目文件，再调用：

```bash
python3 "$SKILL_DIR/scripts/mimo_tts.py" --text-file "$PROJECT/audio/scene-001.txt" --out "$PROJECT/audio/scene-001.wav" --voice '茉莉' --direction '自然、清晰、专业的中文讲解'
```

这是 MiMo `mimo-v2.5-tts` 的按段落合成；默认音色 `mimo_default`，示例的“茉莉”来自原项目，可按用户选择其他可用音色。Key 只通过本机凭据读取并发送给小米官方 `https://api.xiaomimimo.com/v1/chat/completions`，不记录请求头。请求失败时不伪造音频，不覆盖现有已确认音频；用新版本文件名。具体声线及额度以 [官方语音文档](https://mimo.mi.com/docs/zh-CN/quick-start/usage-guide/audio/speech-synthesis) 为准。
